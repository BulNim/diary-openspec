# Design

## Context

`app.js`는 저장소 함수(`loadEntries`, `addEntry`), 목록 그리기(`renderList`: 저장소에서 읽어 `createdAt` 내림차순으로 매번 전체를 다시 그림), 작성 폼 처리로 나뉘어 있다. 각 기록에는 `id`가 이미 있어서 특정 기록을 찾아 고칠 수 있다. 동기는 proposal.md, 동작은 `specs/diary-entries/spec.md`를 따른다.

## Goals / Non-Goals

**Goals:**
- 기존 "매번 전체 다시 그리기" 구조를 유지한 채 수정 상태를 얹는다.
- 작성 흐름(상단 폼, 경고)의 동작은 바꾸지 않는다.

**Non-Goals:**
- 수정 이력이나 `updatedAt` 저장 (표시할 곳이 없으므로 이번에는 두지 않음)
- 여러 탭에서 동시에 수정할 때의 충돌 처리

## Decisions

### 1. 수정 상태는 메모리 변수 하나: `editingId`
- 수정 중인 기록의 `id`만 기억한다(`null`이면 수정 중 아님). `renderList`는 항목마다 `entry.id === editingId`이면 수정 줄, 아니면 보기 줄을 그린다.
- "한 번에 한 기록만"은 이 변수가 하나라서 자연히 지켜진다. 다른 기록의 "수정"을 누르면 `editingId`만 바꿔 다시 그리므로, 이전 기록의 저장하지 않은 입력은 버려진다.
- 대안: 각 줄 DOM을 직접 바꿔 끼우기 → 상태가 DOM에 흩어져 다시 그리기와 충돌한다.

### 2. 수정 줄도 `<form>` 하나로
- 수정 줄은 입력칸 + [저장](submit) + [취소](type="button")를 담은 `<form>`이다. 작성 폼처럼 Enter와 [저장]이 같은 `submit` 경로를 탄다.
- Esc는 입력칸의 `keydown`에서 처리해 [취소]와 같은 함수를 부른다.
- 대안: 입력칸 `keydown`에서 Enter를 직접 처리 → 작성 폼과 처리 방식이 갈린다.

### 3. 저장소 함수 `updateEntryText(id, text)`
- 배열을 읽어 같은 `id`의 `text`만 바꿔 다시 쓴다. `date`·`time`·`createdAt`은 건드리지 않으므로 날짜·시각과 정렬 위치가 그대로 유지된다.
- 성공하면 `true`, 쓰기 실패나 해당 `id`가 없으면 `false`. 실패 시 수정 상태를 유지하고 경고를 보여준다(작성 쪽 저장 실패 처리와 같은 문구).

### 4. 수정 줄의 경고
- 수정 입력칸 바로 아래에 `role="alert"` 문구를 둔다. 빈 내용 저장 시 보이고, 입력칸 `input` 이벤트에서 숨긴다.
- 경고는 다시 그리기 없이 그 요소만 보이고 숨긴다. 다시 그리면 입력 중인 내용과 포커스를 잃기 때문이다.
- 경고가 보이는 동안은 그 줄이 고정 높이(`h-12`)보다 길어진다. 목록 영역의 5개 높이는 그만큼 덜 보이지만 스크롤로 볼 수 있어 수용한다.

### 5. 줄 높이와 레이아웃
- 보기 줄: 날짜·시각 | 내용(말줄임) | [수정]. [수정]은 `shrink-0`로 항상 보이게 한다.
- 수정 줄: 날짜·시각 | 입력칸(남는 폭) | [저장] [취소]. 경고가 없을 때 보기 줄과 같은 `h-12` 높이를 유지해 5개 높이 스크롤 규칙을 깨지 않는다.
- 수정 입력칸에는 그리기 직후 포커스를 주고 커서를 끝으로 보낸다.

### 6. 작성 폼과의 상호작용
- 수정 중에 상단 작성 폼으로 새 기록을 저장하면 목록을 다시 그린다. 이때 `editingId`를 `null`로 돌려 수정 중이던 줄은 저장하지 않고 닫는다. 새 기록이 맨 위에 나타나는 기존 동작을 단순하게 유지하기 위함이다.

## Risks / Trade-offs

- [수정 중 다른 기록의 "수정"이나 새 기록 저장 시 입력하던 수정 내용이 확인 없이 버려진다] → 한 줄 분량이라 손실이 작다. 다른 기록으로 전환하는 경우는 스펙에 명시된 동작이고, 새 기록 저장 시 닫히는 것은 이 설계의 결정(6번)이다.
- [여러 탭을 열어 둔 경우 한쪽의 수정이 다른 탭 화면에는 새로고침 전까지 반영되지 않고, 다른 탭에서 저장하면 덮어쓸 수 있다] → 개인용 단일 탭 사용을 가정하고 수용한다.
- [수정 저장 시 대상 `id`가 이미 없는 경우(다른 탭에서 데이터를 지움)] → `false`를 받아 경고를 띄우고 수정 상태를 유지한다.
