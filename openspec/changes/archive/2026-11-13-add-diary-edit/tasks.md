## 1. 저장소

- [x] 1.1 `updateEntryText(id, text)` 구현: 같은 `id` 기록의 `text`만 바꿔 저장, `date`·`time`·`createdAt`은 유지, 성공 시 `true`·대상 없음이나 쓰기 실패 시 `false`. 콘솔에서 기록 2개를 만들고 하나를 고쳐 그 기록의 `text`만 바뀌고 다른 필드와 다른 기록은 그대로인지, 없는 `id`로 부르면 `false`인지 확인

## 2. 수정 시작과 보기/수정 줄 그리기

- [x] 2.1 `editingId` 상태 추가, 보기 줄 오른쪽에 [수정] 버튼(`shrink-0`) 추가. 목록의 모든 기록에 [수정]이 보이고 긴 내용에서도 버튼이 잘리지 않는지 확인
- [x] 2.2 수정 줄 그리기: 날짜·시각 | 현재 내용이 채워진 입력칸 | [저장](submit) [취소](button)를 담은 `<form>`, 입력칸 아래 숨긴 경고(`role="alert"`), 그리기 직후 입력칸 포커스·커서 끝. [수정]을 누르면 그 줄만 바뀌고 입력칸에 포커스가 있으며 줄 높이가 보기 줄과 같은지 확인
- [x] 2.3 다른 기록의 [수정]을 누르면 `editingId`만 바꿔 다시 그리기. A를 고치던 중 B의 [수정]을 누르면 A는 원래 내용으로, B가 수정 상태로 바뀌고 저장소의 A는 바뀌지 않았는지 확인

## 3. 저장·취소·빈 내용

- [x] 3.1 수정 `<form>` `submit`: `trim` 후 `updateEntryText` 호출, 성공 시 `editingId = null`로 다시 그리기. [저장]과 Enter 각각으로 고친 내용이 그 줄에 보이고, 날짜·시각과 목록 위치가 그대로이며, 새로고침 후에도 유지되는지 확인
- [x] 3.2 [취소] 클릭과 입력칸 Esc 키에서 `editingId = null`로 다시 그리기. 내용을 바꾼 뒤 [취소]·Esc 각각으로 원래 내용이 보이고 저장소도 그대로인지 확인
- [x] 3.3 빈 내용·공백만 저장 시 저장하지 않고 수정 상태 유지 + 그 줄 경고 "내용을 입력해 주세요." 표시, 입력칸 `input` 이벤트로 경고 숨김. 내용을 다 지우고 [저장]·Enter를 각각 눌러 저장소가 그대로이고 경고가 보이는지, 글자를 치면 경고가 사라지는지 확인
- [x] 3.4 `updateEntryText`가 `false`를 돌려주면 수정 상태와 입력 내용을 유지하고 그 줄에 저장 실패 경고 표시. 콘솔에서 수정 중인 기록을 저장소에서 지운 뒤 [저장]을 눌러 경고가 뜨고 입력이 남는지 확인
