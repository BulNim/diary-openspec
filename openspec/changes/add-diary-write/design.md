# Design

## Context

저장소에는 OpenSpec 설정 외에 앱 코드가 없다. 처음부터 만드는 정적 웹 페이지이고, 서버나 빌드 도구 없이 브라우저에서 바로 열리는 형태를 목표로 한다. 동기와 범위는 proposal.md, 동작 요구사항은 `specs/diary-entries/spec.md`를 따른다.

## Goals / Non-Goals

**Goals:**
- `index.html`을 더블클릭하거나 정적 서버로 열기만 하면 동작한다.
- 이후 변경(수정·삭제, 검색)이 붙을 수 있게 저장 로직과 화면 그리기를 분리한다.

**Non-Goals:**
- 빌드 파이프라인, 번들러, 패키지 매니저 도입
- 자동화된 테스트 프레임워크 도입 (이번에는 브라우저에서 수동 확인)
- 다국어, 다크 모드 전환 UI

## Decisions

### 1. 파일 구성: `index.html` + `app.js`
- 마크업과 Tailwind 로드는 `index.html`, 동작은 `app.js`(일반 `<script defer>`)에 둔다.
- `app.js` 안에서 역할을 나눈다: 날짜·시각 포맷 함수, 저장소 접근 함수(읽기·추가), 화면 그리기 함수, 이벤트 연결.
- 대안: 한 파일에 인라인 스크립트 → 작아서 가능하지만 다음 변경에서 바로 커진다. ES 모듈(`type="module"`) → `file://`로 열면 브라우저가 막는 경우가 있어 택하지 않는다.

### 2. Tailwind: Play CDN 스크립트
- `<script src="https://cdn.tailwindcss.com">`로 로드한다. 빌드 없이 유틸리티 클래스를 바로 쓸 수 있다.
- 대안: Tailwind CLI 빌드 → 운영 품질은 좋지만 Node 빌드 단계가 생겨 "파일 하나로 연다"는 목표와 맞지 않는다.
- 결과: 인터넷 연결이 있어야 스타일이 적용된다. (Risks 참고)

### 3. 저장 형식: `localStorage` 키 하나에 JSON 배열
- 키: `one-line-diary.entries`
- 값: 기록 객체 배열을 `JSON.stringify`한 문자열.
  ```json
  [{ "id": "1798706400000", "date": "2026-12-31", "time": "21:40", "text": "올해 끝!", "createdAt": 1798706400000 }]
  ```
- `createdAt`(저장 시점의 `Date.now()`)으로 정렬하고, `id`는 이후 수정·삭제를 위해 미리 둔다(`createdAt` 문자열, 같은 밀리초 충돌 시 접미사).
- `date`·`time`은 저장 시점에 현지 시간으로 만들어 그대로 보관한다. 나중에 시간대가 바뀌어도 쓴 당시의 표시가 유지된다.
- 대안: 날짜별 키(`diary:2026-12-31`) → 같은 날 여러 기록, 전체 최신순 목록에 불리하다.
- 읽을 때 JSON 파싱 실패나 배열이 아닌 값이면 빈 배열로 취급한다(스펙의 손상 데이터 시나리오).

### 4. 날짜·시각 포맷: 직접 조합
- `getFullYear/getMonth/getDate/getHours/getMinutes`와 `padStart(2, "0")`로 `YYYY-MM-DD`, `HH:mm`을 만든다.
- 대안: `toISOString()` → UTC 기준이라 한국 시간 오전 9시 전에는 날짜가 하루 밀린다. `Intl.DateTimeFormat` → 로케일마다 구분자가 달라 형식을 보장하기 번거롭다.

### 5. 목록 그리기와 스크롤
- 저장 후에는 저장소에서 다시 읽어 `createdAt` 내림차순으로 정렬해 목록 전체를 다시 그린다. 기록 수가 적어 충분히 빠르고 상태가 한 곳에만 있다.
- 내용은 `textContent`로 넣는다. 사용자가 쓴 글을 `innerHTML`로 넣지 않아 HTML 삽입을 막는다.
- 목록 컨테이너에 항목 5개 높이의 `max-height`와 `overflow-y-auto`를 준다. 항목 높이를 일정하게 하려고 한 항목은 한 줄로 두고 넘치면 말줄임(`truncate`) 처리한다.

### 6. 입력 처리
- 입력칸과 저장 버튼을 `<form>`으로 묶고 `submit` 이벤트 하나로 처리한다. Enter 키와 버튼 클릭이 자동으로 같은 경로를 탄다. `preventDefault()`로 페이지 이동을 막는다.
- `trim()` 결과가 빈 문자열이면 저장하지 않고 입력칸에 포커스를 둔다.
- 이때 입력칸 바로 아래에 경고 문구 "내용을 입력해 주세요."를 글자로 띄운다. 이 요소에 `role="alert"`를 달아 화면낭독기도 읽게 한다. 입력칸의 `input` 이벤트가 오거나 저장에 성공하면 숨긴다.
  - 대안: `alert()` 대화상자 → 확인 버튼을 눌러야 해서 흐름이 끊긴다. 입력이 비면 저장 버튼 비활성화 → 왜 눌리지 않는지 알려주지 못한다.

## Risks / Trade-offs

- [Play CDN은 오프라인에서 스타일이 빠진다, Tailwind도 운영용으로는 권장하지 않는다] → 개인용 첫 버전이라 수용한다. 필요해지면 Tailwind CLI 빌드로 바꾸는 별도 변경을 만든다.
- [`localStorage`는 브라우저·기기별이고 사용자가 사이트 데이터를 지우면 사라진다] → 이번 범위에서는 수용한다. 내보내기·동기화는 이후 변경 후보.
- [`localStorage` 접근 자체가 막히는 환경(일부 사생활 보호 모드)] → 읽기·쓰기를 `try/catch`로 감싸 화면이 깨지지 않게 한다. 쓰기에 실패하면 입력 내용을 지우지 않는다.
- [자정 직전에 연 화면은 상단 날짜가 다음 날로 바뀌지 않는다] → 상단 날짜는 화면을 열 때 기준으로 표시한다. 저장되는 기록의 날짜는 저장 시점에 다시 계산하므로 기록 자체는 정확하다.
- [긴 한 줄은 목록에서 잘려 보인다] → 말줄임 처리하고 `title` 속성으로 전체 내용을 볼 수 있게 한다.
