# diary-entries Specification

## Purpose

사용자가 하루를 한 줄로 기록하고, 지금까지 남긴 기록을 최신순으로 다시 볼 수 있게 한다.

## Requirements

### Requirement: 오늘 날짜 표시
시스템은 화면을 열었을 때 기기 현지 시간 기준의 오늘 날짜를 `YYYY-MM-DD` 형식으로 SHALL 표시한다. 월과 일은 두 자리로 맞춘다.

#### Scenario: 화면을 열면 오늘 날짜가 보인다
- **GIVEN** 기기 현지 날짜가 2026년 12월 31일이다
- **WHEN** 사용자가 다이어리 화면을 연다
- **THEN** 화면에 `2026-12-31`이 표시된다

#### Scenario: 한 자리 월·일은 0을 붙인다
- **GIVEN** 기기 현지 날짜가 2026년 3월 5일이다
- **WHEN** 사용자가 다이어리 화면을 연다
- **THEN** 화면에 `2026-03-05`가 표시된다

### Requirement: 한 줄 기록 저장
시스템은 사용자가 입력칸에 쓴 한 줄을 저장 버튼 또는 Enter 키로 SHALL 저장한다. 저장되는 기록에는 내용과 함께 저장 시점의 기기 현지 날짜(`YYYY-MM-DD`)와 시각(`HH:mm`, 24시간제)이 포함되어야 MUST 한다. 내용의 앞뒤 공백은 제거하고 저장한다.

#### Scenario: 저장 버튼으로 저장
- **GIVEN** 현재 기기 현지 시각이 2026-12-31 21:40이다
- **WHEN** 사용자가 입력칸에 "올해 끝!"을 쓰고 저장 버튼을 누른다
- **THEN** 날짜 `2026-12-31`, 시각 `21:40`, 내용 "올해 끝!"인 기록이 저장된다

#### Scenario: Enter 키로 저장
- **WHEN** 사용자가 입력칸에 내용을 쓰고 Enter 키를 누른다
- **THEN** 저장 버튼을 누른 것과 같은 결과로 기록이 저장된다

#### Scenario: 저장 후 입력칸 비우기
- **WHEN** 기록이 저장된다
- **THEN** 입력칸이 비워진다

### Requirement: 같은 날 여러 번 작성
시스템은 같은 날짜에 여러 기록을 저장하는 것을 SHALL 허용한다. 새 기록은 기존 기록을 덮어쓰지 않고 별개의 기록으로 추가되어야 MUST 한다.

#### Scenario: 같은 날 두 번째 기록
- **GIVEN** 2026-12-31 09:12에 저장한 기록이 있다
- **WHEN** 사용자가 같은 날 21:40에 새 내용을 저장한다
- **THEN** 두 기록이 모두 남아 있고 각자의 시각이 유지된다

### Requirement: 빈 입력 거부
시스템은 비어 있거나 공백 문자만 있는 입력을 저장하지 SHALL NOT 한다. 이때 기존 기록 목록은 바뀌지 않아야 MUST 한다. 저장을 거부할 때 시스템은 입력칸 바로 아래에 경고 메시지 "내용을 입력해 주세요."를 SHALL 표시한다. 사용자가 다시 입력을 시작하거나 기록이 저장되면 경고 메시지는 사라져야 MUST 한다.

#### Scenario: 빈칸 저장 시도
- **WHEN** 입력칸이 비어 있는 상태에서 사용자가 저장 버튼을 누른다
- **THEN** 아무 기록도 추가되지 않는다
- **AND** 입력칸 아래에 "내용을 입력해 주세요." 경고 메시지가 보인다

#### Scenario: 공백만 입력
- **WHEN** 사용자가 공백만 입력하고 Enter 키를 누른다
- **THEN** 아무 기록도 추가되지 않는다
- **AND** 입력칸 아래에 "내용을 입력해 주세요." 경고 메시지가 보인다

#### Scenario: 경고 후 다시 입력
- **GIVEN** 입력칸 아래에 경고 메시지가 보인다
- **WHEN** 사용자가 입력칸에 글자를 입력한다
- **THEN** 경고 메시지가 사라진다

### Requirement: 기록 유지
시스템은 저장된 기록을 브라우저에 보관하여 페이지를 새로고침하거나 다시 열어도 SHALL 유지한다.

#### Scenario: 새로고침 후에도 기록이 남는다
- **GIVEN** 사용자가 기록을 하나 저장했다
- **WHEN** 사용자가 페이지를 새로고침한다
- **THEN** 저장한 기록이 목록에 그대로 보인다

#### Scenario: 저장된 데이터를 읽을 수 없을 때
- **GIVEN** 브라우저에 저장된 다이어리 데이터가 손상되어 읽을 수 없다
- **WHEN** 사용자가 화면을 연다
- **THEN** 화면은 오류 없이 빈 목록으로 열리고 새 기록을 저장할 수 있다

### Requirement: 최신순 기록 목록
시스템은 저장된 모든 기록을 최신 기록이 맨 위에 오도록 SHALL 표시한다. 각 항목에는 날짜, 시각, 내용이 함께 보여야 MUST 한다. 새 기록을 저장하면 새로고침 없이 목록 맨 위에 바로 나타나야 MUST 한다.

#### Scenario: 최신순 정렬
- **GIVEN** 2026-12-30 22:03, 2026-12-31 09:12, 2026-12-31 21:40에 저장한 기록이 있다
- **WHEN** 사용자가 목록을 본다
- **THEN** 21:40, 09:12, 12-30 22:03 기록 순서로 표시된다

#### Scenario: 저장 즉시 목록 반영
- **WHEN** 사용자가 새 기록을 저장한다
- **THEN** 새 기록이 목록 맨 위에 바로 나타난다

#### Scenario: 기록이 없을 때
- **GIVEN** 저장된 기록이 하나도 없다
- **WHEN** 사용자가 화면을 연다
- **THEN** 목록 자리에 아직 기록이 없다는 안내 문구가 보인다

### Requirement: 5개 초과 시 목록 스크롤
목록 영역은 기록 5개 높이까지 SHALL 표시한다. 기록이 5개보다 많으면 페이지 전체가 아니라 목록 영역 안에서 스크롤하여 나머지 기록을 볼 수 있어야 MUST 한다.

#### Scenario: 5개 이하
- **GIVEN** 저장된 기록이 5개 이하이다
- **WHEN** 사용자가 목록을 본다
- **THEN** 모든 기록이 스크롤 없이 보인다

#### Scenario: 5개 초과
- **GIVEN** 저장된 기록이 8개이다
- **WHEN** 사용자가 목록을 본다
- **THEN** 최신 5개가 목록 영역에 보이고, 목록 영역을 스크롤하면 나머지 3개를 볼 수 있다

### Requirement: 기록 수정 시작
시스템은 목록의 각 기록 옆에 "수정" 버튼을 SHALL 표시한다. 사용자가 "수정"을 누르면 그 기록 줄은 현재 내용이 채워진 입력칸과 [저장]·[취소] 버튼으로 바뀌고, 입력칸에 포커스가 가야 MUST 한다. 날짜·시각 표시는 그대로 보인다.

#### Scenario: 수정 버튼을 누르면 입력칸으로 바뀐다
- **GIVEN** 목록에 "올해 끝!" 기록이 있다
- **WHEN** 사용자가 그 기록의 "수정" 버튼을 누른다
- **THEN** 그 줄에 "올해 끝!"이 채워진 입력칸과 [저장]·[취소] 버튼이 보이고 입력칸에 포커스가 있다

### Requirement: 한 번에 한 기록만 수정
시스템은 동시에 한 기록만 수정 상태로 SHALL 둔다. 다른 기록의 "수정"을 누르면 수정 중이던 기록은 저장되지 않은 채 원래 표시로 돌아가야 MUST 한다.

#### Scenario: 다른 기록 수정으로 전환
- **GIVEN** 기록 A를 수정 중이고 입력칸 내용을 바꿨지만 저장하지 않았다
- **WHEN** 사용자가 기록 B의 "수정" 버튼을 누른다
- **THEN** 기록 A는 원래 내용으로 표시되고, 기록 B가 수정 상태가 된다

### Requirement: 수정 내용 저장
시스템은 수정 상태에서 Enter 키 또는 [저장] 버튼으로 바뀐 내용을 SHALL 저장한다. 내용의 앞뒤 공백은 제거한다. 저장하면 그 기록 줄은 바뀐 내용으로 다시 표시되어야 MUST 하며, 수정한 내용은 새로고침 후에도 유지되어야 MUST 한다.

#### Scenario: 저장 버튼으로 수정
- **GIVEN** "올해 끝!" 기록을 수정 중이다
- **WHEN** 사용자가 내용을 "올해도 끝!"으로 바꾸고 [저장]을 누른다
- **THEN** 그 줄이 "올해도 끝!"으로 표시된다

#### Scenario: Enter 키로 수정
- **GIVEN** 기록을 수정 중이다
- **WHEN** 사용자가 내용을 바꾸고 Enter 키를 누른다
- **THEN** [저장]을 누른 것과 같은 결과로 수정 내용이 저장된다

#### Scenario: 새로고침 후에도 수정 내용 유지
- **GIVEN** 기록의 내용을 수정해 저장했다
- **WHEN** 사용자가 페이지를 새로고침한다
- **THEN** 그 기록은 수정한 내용으로 보인다

### Requirement: 수정해도 날짜·시각과 순서 유지
시스템은 기록을 수정해도 그 기록의 날짜·시각을 바꾸지 SHALL NOT 한다. 목록에서 그 기록의 위치도 바뀌지 않아야 MUST 한다.

#### Scenario: 오래된 기록 수정
- **GIVEN** 2026-12-30 22:03 기록과 2026-12-31 21:40 기록이 있다
- **WHEN** 사용자가 2026-12-31 13:00에 2026-12-30 22:03 기록의 내용을 수정해 저장한다
- **THEN** 그 기록은 여전히 `2026-12-30 22:03`으로 표시되고, 2026-12-31 21:40 기록 아래에 그대로 있다

### Requirement: 수정 취소
시스템은 수정 상태에서 Esc 키 또는 [취소] 버튼으로 수정을 SHALL 취소한다. 취소하면 바뀐 내용은 버려지고 그 기록은 원래 내용으로 표시되어야 MUST 한다.

#### Scenario: 취소 버튼
- **GIVEN** "올해 끝!" 기록을 수정 중이고 입력칸 내용을 "다른 내용"으로 바꿨다
- **WHEN** 사용자가 [취소]를 누른다
- **THEN** 그 줄이 "올해 끝!"으로 표시되고 저장된 내용도 "올해 끝!"이다

#### Scenario: Esc 키
- **GIVEN** 기록을 수정 중이고 입력칸 내용을 바꿨다
- **WHEN** 사용자가 Esc 키를 누른다
- **THEN** [취소]를 누른 것과 같은 결과로 원래 내용이 유지된다

### Requirement: 빈 내용으로 수정 거부
시스템은 비어 있거나 공백 문자만 있는 내용으로 수정을 저장하지 SHALL NOT 한다. 이때 수정 상태는 유지되고, 수정 중인 입력칸 바로 아래에 경고 메시지 "내용을 입력해 주세요."를 표시해야 MUST 한다. 사용자가 다시 입력을 시작하면 경고는 사라져야 MUST 한다.

#### Scenario: 내용을 지우고 저장
- **GIVEN** "올해 끝!" 기록을 수정 중이다
- **WHEN** 사용자가 내용을 모두 지우고 [저장]을 누른다
- **THEN** 저장된 내용은 "올해 끝!" 그대로이고, 수정 상태가 유지되며 "내용을 입력해 주세요." 경고가 보인다

#### Scenario: 경고 후 다시 입력
- **GIVEN** 수정 중인 입력칸 아래에 경고 메시지가 보인다
- **WHEN** 사용자가 글자를 입력한다
- **THEN** 경고 메시지가 사라진다
